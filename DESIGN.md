# Agreed behavior

PHiLLiP is an embeddable PHP toolkit and a standalone local-first application. PHP callers, CLI/TUI, and WebUI share core capabilities. Direct application calls have no permission checks. User-facing contexts enforce administrator policy, user grants, and thread approvals. External data-routing restrictions and obfuscation are deferred.

## Build sequence

Build and validate the smallest end-to-end layer before adding another: Docker/environment; registry; LAN discovery; one-off local profile JSON; single model requests; ephemeral multi-message requests; tools; persisted threads; demo identities and permissions; chat/settings frontend. Add dependencies when needed, not in anticipation.

Prioritize a complete standalone installation before extending ERP integration. Finish `ok-phill` before building `phill`; both remain PHP programs sharing the same core as application calls and the WebUI.

## Common runtime and developer interfaces

Every entry point uses the same bootstrap and lazy class loader, including Composer initialization. Runtime detection, environment configuration, identity, exception handling and diagnostic delivery are centralized; context-specific behavior is conditional, not a separate initialization system.

The standalone runtime owns PHP engine diagnostics: Warning for warnings, Debug for notices/deprecations, catchable exceptions for recoverable/user fatals, and one fatal report for uncaught errors or shutdown failures. Respect suppression/masks; never corrupt stdout, JSON or already-started streams. Unexpected HTTP errors expose generic messages, while source diagnostics remain privileged. CLI `--debug` and `--verbose` are global invocation overrides, with Verbose reserved for raw traces; disabled sinks are not enabled implicitly.

Selected frequently used convenience interfaces accept documented useful input shapes, normalize once, and then call strict internals. Constructors and workflow proxies may recognize arrays, JSON, IDs or other appropriate representations. A safe but uncertain conversion emits a warning; ambiguous or impossible business input throws. This is not a mandate for polymorphic arguments everywhere, nor authorization to build speculative helpers. Logging is deliberately more defensive: arbitrary values, malformed formatting or failed sinks must not interrupt the caller.

Repeated call-site reshaping is evidence that the shared contract is too narrow. Promote recurring shapes to deliberate supported inputs, including row arrays/objects and unique names where meaningful. Progressively hydrate recognized pieces from authoritative database state, configuration/files and safe defaults until the required pieces are present. Keep thin transport adapters and one canonical representation inside each workflow; do not duplicate input recognition in pages, CLI scripts and frontend code. Normalize dirty inputs only where meaning is preserved: trim numeric reference boundaries and CSV items, recognize explicit boolean strings, and validate the result without lossy casts. Passwords/content stay intact, escaping belongs at output boundaries, and authority cannot come from caller-supplied row fields. Foreign-key lookups explicitly select IDs rather than allowing username fallback; non-unique labels are not references.

Reuse expensive prepared handles in repeated database paths, not mutable rows or authorization decisions. The shared statement cache is bounded, tied to exact PDO identity, releases cursors after materializing results, and isolates nested uses. Transaction rollback, deletions and permission changes must remain immediately observable to long-running workers.

`Utilities::cleanup()` centralizes reusable contract-driven normalization without becoming a gatekeeper: known conversions, explicit defaults/cleanup, warnings for permitted guesses, and `Log::writeError()` plus the current partial value on failure. It never throws; callers check their requirements and choose their own failure behavior. JSON decoding is tentative: decode into a temporary array, adopt only usable non-empty containers, then unset the temporary. Empty-container decoding requires explicit opt-in for settings/schema maps. Keep the engine bounded and free of domain hydration or arbitrary callback execution.

`Agent\Log` and browser `PHiLLiPLog` share Verbose -4, Debug -3, Info -2, Warning -1, Success 0, Error 1, Fatal 2. Callers only emit a message; adapters handle authorization, ANSI/CSS, HTTP metadata, browser console, files and optional database logging. Independent thresholds support scoped overrides. Ordinary users never receive privileged console diagnostics. Background run messages use durable events and audience-filtered delivery; PHP fragments restore them after reload. Browser-originated diagnostics stay client-side.

`ok-phill` reserves stdout for the final answer, with all diagnostics on stderr. A plain prompt uses the default profile with zero tools; no prompt requests a short factual server-health greeting. Minimal options select profile, named tools, output contract or frontend session. Root may not use tools or sessions. Unix identity comes from the operating system, not environment variables. Mapped active users receive their authorized memories; unmapped users are limited to organization-wide and current-thread knowledge. Frontend sessions retain normal frontend policy checks.

Explicit CLI `--thread-id new|ID` uses the same persisted Thread/Run pipeline. Continuations are owner-only and reuse their saved profile unless overridden. Ordinary tool grants remain invocation-local; explicitly selected persona defaults are copied and retained. Enqueue and claim happen atomically under the thread lock, without toggling manual policy; busy CLI continuations fail before mutation rather than executing someone else's queued run. Thread IDs are required stderr result metadata, independent of diagnostic thresholds. Profile save/test administration belongs in `phill-models`, reusing shared contracts rather than ad-hoc PHP model clients.

## Local agent teams

`ok-phill agents` and `Tools\\Delegate` share the `Agents` service; the TUI will consume the same API. Workers are named, persona-backed private threads, grouped into local worker teams (not organization ACL teams). Assignments use the existing durable runs, submissions, events and workflow state. Each worker processes tasks sequentially; workers run in parallel, detached from the assigning terminal. Only final answers/results cross agent boundaries; no implicit parent history.

Local workers run under their creator's Unix UID, hostname/container and application identity. Their manual execution flag keeps the generic server worker from running local tools as root; tool-free background indexing still processes agent conversations. A supervisor serializes claims with a session advisory lock and handles bounded cancellation/forced cleanup. Idle queue checks and wakeups share the thread lock. Cancelled, never-started messages remain saved but do not become instructions in later requests.

Delegation is descendant-scoped, bounded to depth two and sixteen agents per team. A child cannot gain tools its parent lacks, including widening a method-only grant into a class grant. Workspaces are inherited; file and command approvals are not. The optional local Workspace tool requires operator-issued thread/workspace grants for exact-file patches/creation and first-three-argv command execution. Grants cannot be self-approved. Authorization and mutation/command acceptance share a thread lock; revocation affects future operations. Commands are literal argv with bounded output, deadlines and process-group cleanup, not an OS sandbox. Approved programs still have the Unix user's authority. Review executable scripts and test actual results.

Management emits JSON stdout and diagnostics stderr, with exit 0 success, 1 failure/stopped, 2 invalid usage, and 3 pending. Explicit removal deletes idle workers, descendants and their private histories. Persona management is available without the web frontend; unmapped Unix users own private personas, and mapped users retain the existing application ACLs.

The engineering catalog installs thirteen organization-default personas without replacing administrator edits unless explicitly requested. Six CLI workflows resolve actual saved persona IDs and tool grants, then create unique durable coordinators and isolated role agents through the same `Agents` service. Workflow phases are coordinator instructions, not a second scheduler; results remain subject to tool evidence, operator approval, tests and independent review.

Source reads include the whole-file SHA-256. Workspace overwrites require that current hash, preserve modes, and publish atomically; exact replacements and exclusive creation remain available. PHP files and PHP shebang scripts are parsed without execution before publication so a truncated generated file cannot disable the shared harness. Repeated identical tool exceptions are bounded independently of rounds, retries and contract correction, with error metadata retained internally but stripped from model payloads.

Engineering SQL research uses a separate restricted PostgreSQL role, curated aggregate views and an operator-refreshed schema snapshot. A small SELECT-only dialect, typed parameters, server-side read-only transactions/privileges, row/byte caps and timeouts are complementary defenses; the tool never exposes the application's PDO connection or private records. This is intentionally not arbitrary business-data SQL access.

## Projects

Projects use a planning Thread and nested ToDos over the existing Run, Request, events, and worker engine. The separate Project scheduler performs readiness checks, dispatches eligible ToDos, and independently reviews every acceptance gate. A ready preflight for the current plan revision is required, but never grants execution: only explicit human Start does. Unfinished planning runs prevent Start. Plan/settings/visibility changes invalidate readiness; completed Projects cannot yet be reopened.

Each ToDo requires title, goal, requirements, context, and nonempty acceptance gates. Incomplete drafts are permitted while planning. Children must finish before parents; task attempts default to three and are configurable from one through ten. Each task owns an isolated conversation with optional persona, its own history, minimal plan metadata, and completed child summaries. Unrelated task histories are not injected. Scoped Project tools derive identity from the current thread and may report findings/evidence/blockers, never start or self-complete tasks.

Completion requires a separate model verdict and specific evidence for every gate. This is an LLM review rather than objective proof or a replacement for offline checks. Unmet gates receive bounded retries; interrupted or uncertain execution stops for explicit investigation and manual retry. Pausing prevents new dispatch and stops/cancels active or queued task runs through shared controls. Project deletion removes its associated execution histories after work is inactive.

The first Project layer has web/memory tools, with neither local filesystem nor remote workspaces. Source, Workspace, SQL, and Delegate cannot enter its execution grants through persona defaults or frontend payloads. Standalone engineering agents retain their existing explicit grants. PostgreSQL remains the release target; SQLite Project support is not a current focus.

ProjectFrontend and ProjectAccess enforce the planning thread's private/team/organization audience, with strict team membership even for owners. Visible collaborators may edit/start/pause; owners alone configure/share/delete. Task conversations inherit the current Project audience and remain runner-managed. PHP owns pages, forms, fragments, and persisted result rendering; browser polling preserves unfinished forms/focus, and only UI preferences live in local storage.

`ok-phill projects` and the browser share this core service. Planning queues a normal agent turn; result reads its latest answer. Prepare requests/waits for readiness without starting. Show exposes snapshots or compact actionable summaries, wait defaults to completed with bounded timeouts, and event IDs support cursors. Local PATH helpers wrap these interfaces rather than adding another agent implementation. See [Projects](docs/projects.md) for current commands, API routes, recovery, and focused tests; functional checks currently use native PHP 8.3 and Docker PHP 8.5. PHP 7.x compatibility is not a testing requirement.

## Requests and tools

`Agent\Request` accepts inline settings or profiles. `send()` returns only the final answer; `$request->response` holds execution details. Transport retries, contract corrections, and agent rounds have separate limits; exhaustion throws. Validate output contracts locally and feed errors back to the model when needed. Tools are callables reflected from signatures and docblocks. Registering a class registers every public static method. Keep those interfaces forgiving and implementation details private or instance-based.

Typed tool arguments share the cleanup contract before invocation, including variadic values. Safe explicit conversions are accepted; malformed booleans, lossy integer casts and nonfinite numbers never silently reach a callable through PHP weak coercion.

Explicit tool-message results retain native content parts through the common Message contract; ordinary results remain text/JSON. Invalid content is caught at the tool boundary and cannot forge call identity. Camoufox screenshots are viewport-bounded PNGs, delivered natively to vision models and rendered safely by PHP. The opt-in Source tool is read-only, CLI-only and workspace-relative; it excludes hidden/private paths and symlinks and bounds file/line/byte reads. Do not grant shell or source-write authority implicitly.

An output completion with finish_reason=length is a failed, preserved partial response, not a reason to retry schema correction or execute incomplete tool calls.

Configuration: database first, JSON fallback, then an exception explaining onboarding or JSON setup. Profiles bind an endpoint, model, and parameters. Discovery stores metadata first. Frontend enablement requires testing the saved configuration and updating actual capabilities; administrators can override capability values. Disabled profiles remain selectable in application code.

Raw metadata is kept in one JSON column per registry record. Capabilities used by PHiLLiP are discrete nullable boolean columns, preserving unknown versus tested/reported true or false. Discovery retains all recognized engines/models/profiles, including disabled, unloaded, and remote/cloud aliases advertised by LAN engines. Admin settings and future benchmarks surface the complete registry.

## Threads

Visibility is exclusively one user, one team, or the organization. Creator owns thread settings/system message. Only message authors edit their own messages; assistant/tool messages cannot be edited. An edit deletes descendants and dangling references, including index entries. Personas replace the editable system prompt directly; edited prompts can be saved as new personas. Personas have the same visibility scopes. Administrators manage default/shared personas, while only owners edit/delete private personas.

Personas contain a name, one freeform system prompt, optional named tools, and optional contract. Do not decompose the prompt or add model requirements. Shared preparation supplies a name preface and editable copies of defaults, not live links; prior assistant messages keep their original names. CLI persona lookup permits only unambiguous names within its authenticated/Unix audience, with IDs resolving ambiguity. Explicit tools/contracts override defaults, never permissions. Both JavaScript-enhanced and ordinary PHP form submissions apply personas through the same policy boundary. Prompt and settings changes commit atomically with respect to enqueueing.

Contracts must be self-contained: local schema references are allowed but validation must not retrieve external files or URLs. Tool-enabled requests use local contract validation/correction without native output grammar that could block tool calls; native structured output remains preferred for tool-free requests.

Messages preserve their entire JSON payload, including settings, in `raw`. One active run per thread. New messages queue and execute sequentially with their own settings. Browser disconnection does not cancel execution. Stop escalates: graceful finish, cancellation, forced process termination. Cleanup precedes the next queued run. Tools publish progress through database events shared by every interface.

Workflow and response state belong in PostgreSQL, not browser memory. Resource-scoped, revisioned state supports thread/run parents and future subagent/project children. Durable live-output projections are rebuildable from events without replaying model requests or tool side effects. Lifecycle authority remains in `runs`. Events, response projections and saved messages commit together; reads use consistent snapshots. Stable submission keys and unique database constraints make network retries idempotent for thread creation and message enqueueing. Reusing a key with different content is a conflict, not another queued message.

Nonessential UI state stays in per-user browser local storage: preferences, unsent conversation settings, panel expansion and navigation hints. The current URL selects the initial server-rendered view. A small avatar cookie mirrors the local preference solely to render the correct SVG immediately in PHP; it is not stored in the database. Unacknowledged submissions retain their delivery key locally so a reload and retry can refer to the same durable server operation.

## Context and knowledge

Prune old reasoning first, then old tool responses, then summarize a middle range in ephemeral context. Keep conversation beginning/recent end, injecting summary between. Preserve tool protocol validity. Original history remains stored except deliberate deletion. Current-thread retrieval becomes available after pruning. A background agent extracts knowledge/embeddings from all new messages after every turn even without Memory. Memory enables explicit knowledge management and cross-thread search constrained by visibility. Contradictions are reconciled by an ephemeral background agent. Remove claims without remaining sources. No dismissal/suppression records.

## Attachments

Native model support first, preferring image representations for vision models. Then per-MIME/extension default parsing profiles, established conversion pipelines, looser usable extraction, and actionable error. No universal extraction contract. Graceful fallback applies throughout the app; never claim unavailable features work.

The first implementation stores immutable originals in PostgreSQL with message-linked references, bounded reusable derivatives and idempotent upload keys. Frontend access inherits current source-thread visibility; application calls remain trusted. Deferred orphan cleanup allows edits to retain source files atomically while deleting descendant-only files. Unlinked uploads expire after 24 hours. Pending attachment drafts stay browser-local and are isolated by conversation, including after composer replacement.

Initial pipelines: direct text/code, native image input, conditional native PDF input, PDF page images for vision, Poppler text extraction, English OCR, and DOCX/ODT ZIP/XML. Native representation is preferred even after OCR/text has been cached. Parsing-profile mappings are database-first with optional JSON fallback; exact MIME, extension, then MIME wildcard. Converter failure or unsupported format is explicit. Attachment preparation/fallback uses the shared durable event/state system; background indexing attempts a textual representation of native attachments too. Reflected file listing/range-reading tools are intrinsic to the current conversation, not cross-thread Memory access.

## Installation and UI

PostgreSQL is required for internal vector/graph features; existing business databases use PDO (initial PostgreSQL/MySQL/MariaDB/SQLite). Onboarding independently maps or creates users/groups/permissions, with read-only/writable choice per mapping. Choose ERP session authentication or standalone login at setup. WebUI works standalone or mounted under an ERP route.

Initial tools: SearchWeb, Fetch, BrowseWeb, Memory, current-thread retrieval. Chat includes streaming, Markdown/code rendering, attachments, model/tool selection, collapsible reasoning/tools, Stop, editing, and persistence. No branching UI. Avatars are developer SVG/CSS packages animated by JS attributes/classes; personal preference independent of personas. Expressive silent text-driven animations, no audio.

PHP owns primary rendering: initial pages, database-backed messages, Markdown, settings and reusable HTML fragments arrive fully rendered from the server. JavaScript owns streaming and interactivity, not a parallel implementation of saved-message rendering. After each response finishes, JavaScript fetches the PHP-rendered thread/message element. Syntax highlighting, animation and live interactions are progressive enhancements; no initial API hydration wait is required.
